# 曲面校正算法调研

日期：2026-09-30。范围：为 SelfWindow 的下一版确定几何模型；此文与交互示意不代表算法已接入桌面程序。

## 目标与关键结论

目标是：平面屏绕轴旋转后，从固定眼点侧看，尽量让每个像素的视线与正对眼睛的参考平面一致。

在单一固定眼点、实体屏和参考面均为平面、忽略镜片畸变时，这个目标的精确连续几何解仍是平面单应性（homography）。它包含透视除法，像素间距会非线性变化，但直线仍映射为直线。不能把“位移随位置呈曲线变化”与“图像的网格线必须弯曲”当成同一件事。[OpenCV：平面单应性](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)

这不是否定曲面观感：若目标改为围绕眼睛的虚拟圆柱、球面，或允许用感知偏好调整局部区域，映射才会超出单个 homography。现有曲面投影算法能支持这种扩展，但不能仅凭“仍不自然”判定应该采用某种曲率。

## 逐像素射线模型

设眼点为 E，目标像素对应空间点 V，实体屏幕中心为 C、法线为 n，水平和竖直单位向量为 a、b。

```text
P = E + λ (V − E)
λ = dot(n, C − E) / dot(n, V − E)
s = dot(P − C, a)
t = dot(P − C, b)
```

把 `(s,t)` 换成物理屏幕像素，即得到目标像素应绘制的位置。分母接近零、交点在眼后或超出屏幕的点不可显示，必须调整有效画面范围。此处是依据射线与平面求交推导的模型。广义离轴投影也以眼点及屏幕空间坐标建立投影；PsychoPy 提供基于 Kooima 方法的现成实现。[PsychoPy 官方文档](https://psychopy.org/api/tools/viewtools.html)

### 仅绕竖轴旋转的例子

设 `E=(0,0,0)`、参考平面 `z=d`，目标像素为 `(x,y,d)`；实体屏中心仍在 `(0,0,d)`，绕竖轴旋转 θ。定义实体屏坐标 `(s,t)` 对应空间位置 `(s cosθ, t, d+s sinθ)`。则：

```text
s = d x / (d cosθ − x sinθ)
t = d cosθ y / (d cosθ − x sinθ)
```

这是本次推导。θ=0 时退化成 `(s,t)=(x,y)`。固定 y 时，由第一式消元可得 `t=y+(y sinθ/d)s`，仍是一条直线；但 `s(x)` 和局部像素间距是非线性的。

数值交叉验证：在 −65°、−40°、0°、40°、65° 五个角度分别取 101×101 个点，比较上述射线公式与仅由四角求出的 H，共 51,005 点；最大坐标误差为 3.331×10⁻¹⁶ 米（浮点舍入量级）。这验证的是理想模型的等价性，不是实际用户眼点已经完成标定。

把两个观察图像的同名像素安排在同一条视线上，可以在选定单眼／中心眼点的连续几何模型中实现重合。实际还受像素离散采样、黑边、分辨率、双眼位置和头部移动影响。物理侧屏的可用视角比正面窄时，无法靠变形生成屏幕以外的光线。

## 现成算法与适用性

| 方法 | 解决什么问题 | 对本项目的判断 |
|---|---|---|
| 视点驱动的离轴投影／射线求交 | 固定眼点看斜放的实体平面，匹配一个正对的参考平面 | 最符合本次明确的“像素视线对齐”目标；可由角度、距离、偏移和尺寸自动生成 H |
| 圆柱／球面重投影 | 用围绕观察者的虚拟曲面组织画面或补偿真实曲面投影 | 适合作为可选的环绕模式；需要明确目标曲面和像素参数化，不能只把现有画面任意鼓起来 |
| Bézier／B-spline 自由形变 | 用控制网格平滑调整边缘、中间及局部比例 | 适合附加的主观微调层；需防止翻折、压缩过大及文字弯曲 |
| Moving Least Squares（MLS） | 根据少量控制点或线段生成平滑形变，含仿射、相似和刚性变体 | 可用于拖拽式局部微调；并非自动的物理视点标定 |
| Panini | 降低超广角场景的边缘拉伸，保留特定直线结构 | 更偏全景与三维场景，日常桌面不宜默认使用；需要已知投影含义和视场角 |

圆柱投影的标准做法是建立观察／投影几何，追踪射线与曲面的交点，而不是用任意桶形畸变替代。[Paul Bourke：圆柱投影图像变形](https://paulbourke.net/panorama/cylinder/)

商业软件中也明确区分透视变形与曲面变形。QLab 的曲面 Bézier 模式使用每块 16 个控制点；MadMapper 的网格编辑提供 Bézier 曲线。[QLab 官方文档](https://qlab.app/docs/v5/video/video-output/)、[MadMapper 官方网格说明](https://madmapper.com/files/05-Mesh%20Warping.pdf)

MLS 论文提供了利用点或线段控制仿射、相似、刚性形变的闭式求解方法。其“保持局部形状”的偏好与“严格沿视线对齐”的目标不同，不能未经测试就宣称它更适合文字。[Schaefer、McPhail、Warren，2006，作者论文](https://people.engr.tamu.edu/schaefer/research/mls.pdf)

Panini 的目标是超广角透视图像中横向视角的压缩和特定直线的保持；论文讨论的是宽视野场景的视觉外观，不能直接作为桌面阅读舒适度的证据。[Sharpless、Postle、German，2010](https://diglib.eg.org/items/29b67abe-d80e-4010-a065-e8292a8c65ef)

## 建议的下一版

根据当前明确的目标，建议先做“视点标定 + 可选曲面”，而不是把所有桌面强制弯曲。

1. 保留已有四角模式和配置兼容，增加按物理模型生成校正的模式：屏幕实际宽高、相对视线角度、观看距离、眼睛水平／竖直偏移。当前手工四角只保证用户指定的四个对应点，不保证这些点恰好对应真实眼点和理想参考平面。
2. 在同一个射线框架中提供目标面切换：平面、圆柱。圆柱增加曲率／角跨度和轴方向；轴在观看坐标中定义，不能因横屏旋转为竖屏而错误交换。
3. 若物理标定后仍希望局部微调，再增加 4×4 三次 Bézier 或 B-spline 残差层。控制点界面可先暴露边中点等少量手柄，插值模型和实际可拖动手柄不必一一对应。不能把 3×3 网格直接称作三次 Bézier 曲面。
4. 用实时文字、方格、圆、横竖线进行 A/B；分别评价固定眼点的几何误差和用户阅读舒适度。

### 与当前代码的衔接

- `src/geometry.h` 的 `Homography::map` 已经使用齐次除法；当前实现不是简单的线性拉伸。
- `src/graphics.cpp` 使用 H 的逆变换对每个输出像素采样。新增平面物理标定仍可复用这条渲染路径。
- 曲面模式可令输出像素发出射线，与虚拟目标面求交，再求源纹理坐标，直接在像素着色器中做逆映射；也可预计算纹理坐标查找表或细分网格。
- 鼠标热点必须使用同一个前向映射；渲染与鼠标不要各自拟合不同变形，否则会再次出现点击错位。
- 自由形变需检查局部雅可比行列式、边界自交以及三角形方向。只采样检查雅可比不能证明整个连续曲面全局可逆；实现上需要约束控制点位移并对网格折叠明确拒绝。

以上是适配本项目的工程建议，不是现有资料保证的最终视觉效果。
